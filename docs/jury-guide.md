# Краткий запуск бота

Нужны исходный код проекта, работающие Docker с Compose v2 и интернет. Запуск одинаковый для систем, поддерживающих Docker с Linux-контейнерами; GPU не требуется.

1. Откройте папку проекта с `compose.yaml`. Переданный командой файл `jury.env` переименуйте в `.env` и поместите в эту папку. В нём уже заполнены настройки:

   | Переменная | Назначение |
   | --- | --- |
   | `MAX_BOT_TOKEN` | Токен доступа к API бота MAX |
   | `POSTGRES_PASSWORD` | Пароль PostgreSQL |
   | `OLLAMA_MODEL` | Локальная модель `qwen3.5:2b-q4_K_M` |
   | `AI_DEVICE` | `cpu` — работа на процессоре |

   Ключи платных нейросетей и поисковых API не нужны. Адреса БД и Ollama задаёт Docker Compose. `ADMIN_TOKEN` нужен только для дополнительной админки; `MAX_WEBHOOK_SECRET`, `MAX_WEBHOOK_URL` и `BOT_DOMAIN` — только для режима webhook. Для этого запуска они не требуются.

2. Остановите другой экземпляр с тем же токеном, если он запущен. У бота не должно быть зарегистрированного webhook. Выполните в папке проекта:

   ```bash
   docker compose --profile polling up -d --build
   docker compose --profile polling ps -a
   ```

   При первом запуске модель скачивается автоматически — около 1,9 ГБ. Дождитесь `model-init: Exited (0)` и работающих `worker` и `polling`.

3. Откройте в MAX **@t439_hakaton_max_bot**. Отправьте `/start`, затем `/consent`, выберите «Подготовиться к регистрации» и ответьте на вопросы. Проверьте `/profile`, `/checklist`, `/pdf`, `/steps`. Для вопроса по документам: `/ask Как заполнить Р21001?`. Каждую команду отправляйте отдельно. При использовании собственного токена откройте соответствующего бота.

Просмотр логов:

```bash
docker compose logs -f worker polling
```

Остановка с сохранением данных:

```bash
docker compose --profile polling down
```
