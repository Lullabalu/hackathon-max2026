# Пользовательские сценарии

| Сценарий | Реализация |
| --- | --- |
| Первичная консультация | `/start`, отдельное согласие, выбор цели, сохранение прогресса |
| Подбор деятельности | Уточнение описания, поиск ОКВЭД, подтверждение пользователем |
| Выбор налогового режима | Анкета, адаптивные вопросы, сравнение, явный выбор |
| Расчёт нагрузки | Расчёт по сохранённым данным, ограничения и недостающие параметры |
| Подготовка документов | Персональный чек-лист, PDF, частичный черновик Р21001 |
| Шаги регистрации | Пошаговое сопровождение и ссылка на официальный сервис |
| Вопросы и FAQ | Локальная справка и поиск официальных материалов с выжимкой |
| Напоминания | Отдельное согласие, часовой пояс, поддерживаемые сроки и ручные даты |
| Подача заявления | Пользователь самостоятельно подаёт документы; API подачи не подключён |
| Изменение условий | `/set`, пересчёт и повторная проверка выбранного режима |
| Новости | Добровольная подписка и рассылка опубликованных администратором материалов |
| Администрирование | Версии FAQ, новостей и правил, предпросмотр, публикация и откат |

## Существенные ограничения

- Налоговые правила и календарь рассчитаны на 2026 год. Индивидуальные льготы, региональные ставки и специальные продления могут требовать уточнения.
- Поддерживаются НПД, УСН, ПСН, АУСН и ОСНО в пределах имеющихся данных. Неполные расчёты не превращаются в подтверждение права на режим.
- Подбор ОКВЭД не заменяет полную проверку лицензий и ограничений деятельности.
- Р21001 содержит только часть полей. Подпись, паспорт, адрес и остальные сведения заполняет пользователь.
- Регистрация в ЕГРИП и дата сохраняются со слов пользователя; автоматической проверки статуса нет.
- Напоминания охватывают поддерживаемую часть календаря. Пользователь может создать дополнительные даты вручную.
- Генерация PDF и API загрузки проверяются отдельно от фактической доставки в пользовательский чат.
- Модель может ошибаться: ответ содержит ссылки для проверки, а недостаточные данные вызывают уточнение или сообщение об отсутствии подтверждения.

## Проверка

`python -m scripts.check_spec` выполняет сценарии в отдельной схеме демонстрационной БД без отправки сообщений в MAX. Автоматические тесты проверяют диалог, персонализацию, расчёты, документы, хранение и доставку. `python -m scripts.benchmark` дополнительно вызывает настоящую модель и источники. Команды и переменные описаны в [руководстве разработчика](development.md).
