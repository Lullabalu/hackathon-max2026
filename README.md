# MAX · Помощник предпринимателя

Бот для MAX, который помогает подготовиться к регистрации ИП: разобраться с ОКВЭД, сравнить налоговые режимы и собрать документы. Бот задаёт уточняющие вопросы и учитывает сохранённую анкету в следующих ответах.

**Python · PostgreSQL · Ollama / Qwen3.5 · Docker Compose**

## Возможности

- Пошаговая консультация с сохранением прогресса и исправлением ответов.
- Подбор ОКВЭД по официальному классификатору ФНС и уточнение неоднозначной деятельности.
- Предварительное сравнение налоговых режимов по параметрам бизнеса.
- Персональный чек-лист, PDF и частично заполненный черновик Р21001.
- Ответы на свободные вопросы: поиск в официальных источниках, краткая выжимка и ссылки.
- Напоминания, подписка на новости и администрирование справочников.

Приветствия и обычные вопросы о боте обрабатываются без поиска. Данные анкеты сохраняются после согласия пользователя. Для генерации используется локальная модель; платные AI API и поисковые ключи не нужны.

## Быстрый запуск

Нужны Docker с Compose v2, доступ в интернет и токен бота MAX. GPU не требуется. Модель по умолчанию — `qwen3.5:9b`, загрузка весов занимает около 6,6 ГБ. Предусмотрите дополнительную память и диск для контекста модели, контейнеров и PostgreSQL; скорость зависит от ресурсов сервера.

1. В репозитории есть `.env` с шаблоном настроек. Создайте случайные секреты:

   ```bash
   python3 scripts/init_env.py
   ```

   Укажите `MAX_BOT_TOKEN` в `.env`. Скрипт заменяет нетронутый шаблон и сохраняет существующие рабочие настройки. Если команда передала заполненный `.env` приватно, используйте его вместо шаблона.

2. Запустите сервисы:

   ```bash
   docker compose --profile polling up -d --build
   docker compose --profile polling ps -a
   ```

   При первом запуске дождитесь завершения `model-init` с кодом `0`. Worker начнёт обработку после загрузки модели.

3. Откройте своего бота в MAX и отправьте `/start`. Подтвердите согласие командой `/consent` и следуйте вопросам.

Для одного токена запускайте один экземпляр polling; зарегистрированный webhook нужно отключить перед использованием этого режима. Для сервера с доменом предусмотрен [запуск через webhook](docs/deployment.md#webhook).

```bash
# Логи
docker compose logs -f worker polling
# Остановка с сохранением данных
docker compose --profile polling down
```

## Основной сценарий

1. `/start` → `/consent` → цель «Подготовиться к регистрации».
2. Опишите деятельность и подтвердите предложенный ОКВЭД.
3. Ответьте о регионе, доходе, расходах, сотрудниках и клиентах.
4. Посмотрите сравнение налогов, уточните условия и выберите режим.
5. Укажите гражданство, возраст и способ подачи документов.
6. Получите чек-лист и PDF; пройдите шаги подготовки регистрации.

В любой момент можно задать отдельный вопрос через `/ask`, посмотреть `/profile` и вернуться к маршруту через `/continue`.

## Команды

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Начать консультацию и открыть справку |
| `/profile`, `/set поле значение` | Посмотреть и изменить анкету |
| `/continue`, `/back`, `/chat` | Продолжить, вернуться или приостановить маршрут |
| `/okved описание` | Подобрать коды деятельности |
| `/taxes`, `/tax режим` | Сравнение и подробности налогового режима |
| `/register`, `/checklist`, `/pdf` | Подготовка регистрации и документы |
| `/form`, `/form pdf` | Частичный черновик Р21001 |
| `/ask вопрос`, `/sources` | Вопрос по официальным материалам и источники |
| `/reminders`, `/subscribe`, `/unsubscribe` | Напоминания и новости |
| `/privacy`, `/delete` | Условия хранения и удаление данных |

## Как устроен проект

```text
ip_bot/        логика диалога, поиск, модель, API MAX и хранилище
config/        источники, ОКВЭД, налоговые правила и шаблоны документов
docker/        настройки HTTPS и инициализация PostgreSQL
docs/          запуск, архитектура и сценарии проверки
scripts/       служебные команды и проверки
tests/         автоматические тесты
compose.yaml   запуск сервисов
.env.example   описание переменных окружения
```

PostgreSQL хранит профиль, состояние диалога, очередь и кэш источников. Модель получает релевантные данные анкеты и найденные фрагменты. Ответ проверяется на соответствие источникам; при неудаче бот повторяет подготовку и при необходимости уточняет поиск. Общего ограничения времени обработки нет. `AI_TIMEOUT_SECONDS=0` отключает таймер генерации; сетевые и SQL-таймауты обрабатывают технические сбои.

## Проверки и разработка

```bash
python3.13 -m venv .venv
# Активируйте .venv в своей оболочке
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests
```

Команды установки и проверки выполняйте в активированном виртуальном окружении. Для интеграционных тестов задайте `TEST_DATABASE_URL` на отдельную PostgreSQL-базу; без неё проверки БД пропускаются. [Дополнительные проверки](docs/development.md) включают сценарии диалога и настоящую локальную модель.

## Границы решения

Расчёты основаны на правилах 2026 года и введённых данных. Региональные льготы и индивидуальные условия могут требовать уточнения. Р21001 — частичный черновик: паспорт, адрес и подпись пользователь заполняет самостоятельно. Бот не подаёт документы в ФНС и не проверяет факт регистрации в ЕГРИП автоматически. Поиск ограничен каталогом официальных источников; ссылки позволяют проверить ответ.

В Git хранится только шаблон `.env`, без рабочих токенов. Локальные секреты можно хранить в `.env.local` — этот файл исключён из Git. Для запуска перенесите его содержимое в `.env`; заполненный `.env` не включайте в коммит. Пользовательские данные, резервные копии и веса модели также исключены из Git.
